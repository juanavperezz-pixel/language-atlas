# Language Atlas — My Learning Studio

A mobile-friendly, local-first learning academy and personal knowledge library for **Korean, Mandarin Chinese, Russian, and Italian**.

**Version:** 1.0 starter · **Stack:** vanilla HTML, CSS, JavaScript · **Hosting:** GitHub Pages · **No API keys, database, or build step required**

![Language Atlas desktop dashboard](preview-desktop.png)

## What's in the first build?

- One dashboard for four languages, with distinct beginner/review tracks.
- **8 starter lessons** (2 per language), with explanations, vocabulary, listening buttons, and interactive quizzes.
- **40 vocabulary flashcards** with a basic due-date review schedule (browser storage).
- **8 reference-library cards** plus a searchable, editable personal notes library.
- Guided writing prompts with a saved practice journal.
- Lesson completion, quiz history, study activity, and a study-day streak.
- Local JSON export/import of your progress, journal, and notes.
- Responsive layout with consistent **Menu** navigation on mobile.

This is a functional starter—not a complete curriculum or a replacement for live language feedback. Writing practice is not auto-graded. Speech is generated by the device's browser voices, and pronunciation quality varies.

## Publish to GitHub Pages

**Important:** On GitHub Free, Pages requires a **public repository**. GitHub Pages websites are generally **publicly accessible**, including those published from private repositories on plans that support it. **Do not commit private notes, secrets, API keys, or exported backups to this repository.** Your personal notes are intentionally stored in your browser, not committed to the project.

### Method A — easiest: GitHub Desktop (no command line)

1. Create a new repository named `language-atlas` at https://github.com/new. Choose **Public** if you want free GitHub Pages publishing. Do **not** initialize it with a README, since one is already included in this starter.
2. Install [GitHub Desktop](https://desktop.github.com/) if needed, then use **File → Clone repository** to clone your empty repository onto your computer.
3. Unzip `language-atlas-starter.zip`. Copy the **contents** of the extracted `language-atlas` folder (including the `docs` folder) into the clone's top-level folder. Do not copy the outer folder as an additional nested folder.
4. In GitHub Desktop, enter a summary such as `Launch Language Atlas`, click **Commit to main**, then **Push origin**.
5. On GitHub, open the repository and go to **Settings → Pages**.
6. In **Build and deployment**, set **Source** to **Deploy from a branch**; choose branch **main**, folder **/docs**, and click **Save**.
7. Once deployment completes, open `https://YOUR_USERNAME.github.io/language-atlas/` (replace `YOUR_USERNAME` with your GitHub username).

### Method B — using Git

Create a new empty GitHub repository as above, then unzip the project and run in the project folder:

```bash
git init
git add .
git commit -m "Launch Language Atlas"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/language-atlas.git
git push -u origin main
```

Then configure **Settings → Pages → Deploy from a branch → main → /docs**.

GitHub's official docs: [Configuring a publishing source](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site) and [Creating a GitHub Pages site](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site).

### Open locally before publishing

You can open `docs/index.html` in your browser. If your browser restricts local-file storage, run a simple local HTTP server instead:

```bash
cd language-atlas/docs
python -m http.server 8000
```

Then visit `http://localhost:8000`. On Windows, `py -m http.server 8000` may be needed instead of `python`.

## How to study

1. Open **Dashboard** and choose a track; **Lessons** contain a brief explanation, sample sentences, vocabulary, and quizzes.
2. In a quiz, select an answer, click **Check answer**, and if wrong, choose a different option and try again. You can return to the lesson any time.
3. Mark a lesson complete when you feel comfortable. Completion is independent of quizzes, so use your judgment.
4. Open **Flashcards** to recall vocabulary. **Again**, **Good**, and **Easy** schedule your next review (simple intervals, not a sophisticated mastery score).
5. Open **Library** to write/search/edit/delete private notes. **Practice** saves responses to a private writing journal.
6. Open **Settings** regularly and **Download my backup**. The backup can be imported to another browser or device.

**Sync warning:** Browser storage is specific to the browser/device and can be deleted by clearing site data or using private browsing. GitHub does NOT automatically sync saved notes or progress across devices. Use export/import until a proper authenticated cloud sync is added.

## How to edit the curriculum

Open `docs/data.js`. The `languages` array contains information about each track. The `lessons` array contains lesson objects with:

- `id`, `language`, `unit`, `title`, `level`, `minutes`, `description`
- `outcomes` (learning objectives) and `explanation`
- `examples`: native-language text, reading, English meaning
- `vocab`: arrays of `[word, reading, meaning]`
- `quiz`: `{question, options, correct, why}` where `correct` is a **zero-based option index**

To create a new lesson, duplicate an existing object, change its `id` to a unique value (e.g. `it-food`), and update the content. The app will automatically list it under the correct track, incorporate its vocabulary into flashcards, and update lesson totals.

The `resources` array supplies public/static reference-library cards. Personal notes entered on the website are **not** added to `data.js` or GitHub.

## Privacy and security

- There are no logins, accounts, trackers, external JavaScript libraries, or AI API requests.
- Public curriculum/source files on GitHub Pages are visible to others. Do not put personal journaling or private materials in the repository.
- Progress, note bodies, flashcard review intervals, and journal entries are kept in **localStorage** in your browser. This is convenience storage, **not encrypted storage**.
- Downloaded JSON backups contain your personal data in plaintext; keep them in a private location.
- The importer expects a compatible Language Atlas v1 JSON file and will ask before replacing current local data.
- If you need password-protected private access or automatic cross-device sync, plan to add an authenticated backend instead of relying on GitHub Pages alone.
